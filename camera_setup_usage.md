# Camera / Robot Pose Setup Tutorial (`scripts/inspect_scene.py` + `scripts/gen_camera_poses.py`)

Workflow for picking `VIEWER_CAMERA_POS/ORN`, `robot_config["position"/"orientation"]`,
and `EXTERNAL_CAMERA_CONFIGS` values when authoring a new BEHAVIOR-1K task file
under `oopsiebench/envs/behavior1k/`. Both scripts are read-only reuses of
`scripts/teleop_b1k.py`'s `TASK_REGISTRY`/env-building helpers — neither script
modifies `teleop_b1k.py` itself.

## 1. Find a good camera pose interactively (`inspect_scene.py`)

```bash
python scripts/inspect_scene.py --task_name nav_to_table_02
```

This loads the task's scene/robot/objects with the **normal Isaac-Sim editor
layout intact** (Stage tree, Property panel, Timeline all visible/dockable —
unlike `teleop_b1k.py`, which hides everything but the Viewport for clean
recordings). Camera/gizmo navigation is 100% native Kit:

- Right-click + drag — look around; hold right-click and press WASD to fly
- Alt + LMB/MMB/RMB drag — orbit / pan / zoom around a pivot
- Viewport toolbar icons (not W/E/R — see Gotcha #1 below) — Move / Rotate / Scale gizmo on a selected prim
- `F` — frame the selected object

Keys this script adds on top of that:

- **`P`** — print the current viewer camera pose, every robot's pose, and
  every `task_objects` entry's pose (position + xyzw quaternion) to the
  terminal. This is the main output of this step — copy the printed values
  into the task file.
- `SPACE` — toggle play/pause of physics stepping (Kit's own Timeline widget
  is visible but does **not** drive OmniGibson's physics, which is stepped
  explicitly from Python — `SPACE` is the real control).
- `ESC` — quit.

Typical loop: orbit/fly to a framing you like (and/or drag the robot or an
object with the Move gizmo), press `P`, copy the numbers you need:

- Camera pose → `VIEWER_CAMERA_POS` / `VIEWER_CAMERA_ORN` and
  `EXTERNAL_CAMERA_CONFIGS["external_sensor_0"]` in the task file.
- Robot pose → `robot_config["position"]` / `["orientation"]`.
- Object pose → the matching entry in `TASK_OBJECTS`.

## 2. Generate the rest of the multi-camera set (`gen_camera_poses.py`)

Convention in this repo: `external_sensor_0` is the hand-picked pose from
step 1; the remaining cameras are generated by rotating it around its
inferred look-at target on a horizontal plane, keeping height/radius fixed:

- **Franka/droid-style tasks (2 cameras total):** rotate by **+60°** →
  `external_sensor_1`. See `open_drawer.py`'s comment.
- **Tiago/behavior-style tasks (3 cameras total):** rotate by **+60°** and
  **-60°** → `external_sensor_1` / `external_sensor_2`. See `nav_to_table.py`'s
  comment.

```bash
python scripts/gen_camera_poses.py \
    --position <sensor_0 x> <sensor_0 y> <sensor_0 z> \
    --orientation <sensor_0 x> <sensor_0 y> <sensor_0 z> <sensor_0 w> \
    --angles 60 -60 --task_name nav_to_table_02
```

Prints ready-to-paste `"external_sensor_N": {...}` blocks. Always check the
printed **self-check angle error** first:

```
# inferred target: [...]
# self-check angle error vs original orientation: 0.0 deg  (ok)
```

A large error (the script warns above 10°) means the camera isn't looking at
a sensible point on the assumed `--target_z=0.75` plane (e.g. it's pointed
straight down — see Gotcha #2) — fix the input pose or pass `--target x y z`
explicitly before trusting the output.

### Rendering an actual visual check, not just numbers

Add `--task_name` (and optionally `--headless` to skip the GUI window) to
also load the scene and save a `.jpg` per viewpoint (`external_sensor_0`
included) under `camera_check/gen_camera_poses/<task_name>/`:

```bash
python scripts/gen_camera_poses.py \
    --position ... --orientation ... --angles 60 -60 \
    --task_name nav_to_table_02 --headless
```

### Nudging a single already-generated camera

If, after looking at the rendered images, one viewpoint needs a small tweak
(e.g. "`external_sensor_2` should be a bit further forward") — don't
re-derive the whole rotated set. Re-paste that camera's own current
position/orientation and nudge it along its own local axes:

```bash
python scripts/gen_camera_poses.py \
    --position <external_sensor_2's current x y z> \
    --orientation <external_sensor_2's current x y z w> \
    --label external_sensor_2 \
    --nudge_forward 0.3 \
    --task_name nav_to_table_02 --headless   # re-render to confirm, optional
```

- `--nudge_forward/--nudge_right/--nudge_up` translate along the camera's own
  local axes (OpenGL convention: forward = local -Z, right = local +X,
  up = local +Y); orientation is left unchanged.
- `--label` controls what name the (possibly nudged) input pose is printed/
  rendered under — default is `external_sensor_0`, so set it to whichever
  camera you're actually adjusting.
- `--angles` is optional — omit it to just nudge/inspect one pose with no
  rotated copies generated.

### Run history

Every invocation appends one JSON line (timestamp, all CLI args, all poses
produced) to `--log_path` (default: `camera_check/gen_camera_poses/poses_log.jsonl`).
Pass `--log_path ""` to disable. Read it back with e.g.:

```bash
cat camera_check/gen_camera_poses/poses_log.jsonl | python3 -c \
    "import sys, json; [print(json.dumps(json.loads(l), indent=2)) for l in sys.stdin]"
```

## Gotchas

1. **`W`/`E`/`R` do not open the Move/Rotate/Scale gizmo, and right-click-held
   WASD fly doesn't work either — this is OmniGibson itself, not a bug in
   either script.** `OmniGibson/omnigibson/simulator.py`'s `_launch_app()`
   deregisters **every** Kit hotkey at startup ("these ... cause collisions
   with the OmniGibson-provided hotkeys"), unconditionally, for any
   OmniGibson-based script. Use the **Viewport's toolbar icons** (Move /
   Rotate / Scale / Select) instead — those trigger the same tools via direct
   mouse clicks, not the deregistered hotkeys.

2. **A near-identity camera orientation means "looking straight down" —
   rotating around the inferred look-at point then does nothing** (position
   sits directly on the vertical rotation axis, radius ≈ 0, so all generated
   cameras collapse back to the same pose). If `gen_camera_poses.py` prints
   an unchanged position for every generated `external_sensor_N`, re-orient
   the source camera (in `inspect_scene.py`, right-click-drag to look at the
   scene from an angle, not top-down) and re-capture with `P`.

3. **Shell-quoting negative numbers in scientific notation (e.g.
   `-4.66e-10`) breaks argparse** — `--position`/`--orientation` use
   `nargs=N`, and argparse's negative-number detection doesn't recognize
   scientific notation, so it mistakes the token for an unrecognized flag
   ("expected N arguments" error). These tiny values are floating-point noise
   from a near-zero quaternion component anyway — just round them to `0`
   (or a plain decimal like `-0.0000000004656`) before pasting into the
   command.

4. **`--position`/`--orientation` values are space-separated, not
   comma-separated** (`nargs=3`/`nargs=4` under the hood) — `--position -1 2 3`,
   not `--position -1, 2, 3`.

5. **`--log_path` must be a file path, not a directory** — passing an
   existing directory (e.g. reusing a `--render_dir` value by mistake) used
   to crash with `IsADirectoryError`; `gen_camera_poses.py` now detects this
   and falls back to `<that_dir>/poses_log.jsonl` with a warning instead, but
   it's clearer to just point `--log_path` at a `.jsonl` file (or omit it and
   use the default) from the start.
